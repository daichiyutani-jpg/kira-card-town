# 友達との対戦（オンライン）のしくみ

## 使い方
1. 招待する人：メニュー（またはタイトル）→「友達と対戦」→「部屋をつくって招待する」→「LINEで招待を送る」
2. 招待された人：届いたURLを開く → 出てきた「返事コード（KIRAR1-…）」を「LINEで返事を送る」
3. 招待した人：届いた返事コードを貼りつけて「つなぐ」→ 対戦開始

招待した人は、つながるまでその画面を開いたままにする。

## 使っている外部サービスと費用
| もの | 用途 | 費用 | 登録 |
|---|---|---|---|
| WebRTC（ブラウザの標準機能） | 2台のスマホを直接つなぐ | 無料 | 不要 |
| Google の公開 STUN サーバー（stun.l.google.com:19302） | 自分の外から見たアドレスを調べる | 無料 | 不要 |
| LINE の共有URL（line.me/R/share） | 招待・返事を送る（本人が送信を押す） | 無料 | 不要 |

- ゲームのサーバーは置いていない。秘密の鍵・APIキーはどこにも入れていない。
- STUN に送られるのは接続のための問い合わせだけで、対戦の中身・セーブは送らない。
- 招待URLの `#` から後ろ（接続情報）はWebサーバーには送られない。ただし接続情報には端末のIPアドレスが入るので、対戦する相手にだけ送る。

## 公平さ・ずる対策
- **最初の乱数（シード）**：二人がそれぞれ乱数を決め、まず SHA-256 のハッシュだけを送り（コミット）、そろってから中身を見せる（公開）。ハッシュと合わない時は中止。片方が都合のいいシードを選べない。シード＝二人の乱数のXOR。
- **毎手の確認**：行動を受け取ったら、ルールのエンジン（`applyAction`）で合法か確かめてから同じ計算をする。違反なら中止。
- **状態のずれ**：毎手、送る側が「行動後の状態のハッシュ」を付け、受けた側は自分の計算結果と比べる。ずれたら中止。
- **デッキ**：20枚・同名3枚まで（URは1枚）などのルールを確認。違反なら接続しない。
- **版**：通信の版（NET_VERSION）が違えば接続しない。
- **端末の時計**：使わない（シードはコミット公開で決める）。
- **限界（正直に）**：サーバーがないため「そのカードを本当に持っているか」は確かめられない。そのため、オンライン対戦ではカードもコインも増えない（勝敗の記録だけ）。

## 切断
- 4秒ごとに生存確認を送り、25秒何も届かなければ切断とみなす。接続が切れた・おかしな通信が届いた・状態がずれた時は「中止」になり、**勝敗は記録しない**。
- こうさんした時は、相手の勝ちとして記録する。
- 再接続はできない（もう一度招待からやり直す）。

## つながらない時
- TURN サーバー（中継）を置いていないため、会社・学校のWi-Fiや一部のモバイル回線（どちらも厳しいNATの時）ではつながらないことがある。別の回線で試す。
- 中継が必要になった場合の案：Cloudflare の TURN（有料・従量）や自前の coturn（サーバー代）。**費用が出るので、使う時は先に相談する。**

## 確認したこと
- 自動テスト（`tests/flow.test.ts`）：招待URL・返事コードの読み取り、コミット公開、メッセージの検査、同じシードなら同じ状態になること。
- ブラウザの総合テスト（`npm run test:e2e`）：同じPCの2つの画面で、招待 → 返事 → 接続 → ターン交代の同期 → こうさんで相手が勝ち、まで確認。
- **未確認**：別々のスマホ・別々の回線どうしでの対戦。
